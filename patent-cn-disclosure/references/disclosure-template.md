# 交底书模板与各章写法（成文必读）

结构总览（经真实案件九轮修订确认的终态；`assets/交底书骨架.md` 为占位版）：

```
文档头部（信息表格：案号/交底书名称/申请人/发明人/撰写人/撰写人电话/E-mail ＋ 注意事项·红字机制见 docx-format.md §4）
缩略语和关键术语定义            ← 新增节（高频术语前移集中定义）
一、技术背景与现有技术          ← 1.1 现有技术 / 1.2 现有技术存在的缺点（≤6条）
二、本发明所要解决的技术问题
三、技术方案详细阐述            ← 3.1 场景与总体思路 / 3.2 系统框图 / 3.3 模块功能
                                   3.4 方法流程（S1–Sn）/ 3.4.1 公式（逐式符号说明）
                                   3.5 关键技术参数
四、替代方案与可选实施路径      ← 前移独立成章（3–4点；原"可选实施方式"并入此章，不再单设）
五、与现有技术相比的有益效果    ← ≤6条
六、技术关键点和欲保护点        ← 6.1 技术特征关键点（≤6条）/ 6.2 优选特征
七、实施例及其它                ← ≤2个，小节带 7.x 节号（"7.1 实施例一：〔实施例名〕"）
### 附图说明 / ### 参考文献      ← 末尾两节（三级标题挂七章后；尾部说明括号红字）
```

**文风规则（成文时逐条遵守，细则与审查机制见 `defensive-writing.md`）**：括号内容≤段落1/3且禁嵌套；破折号禁连用；禁生僻自创词；不刻意凝练（反四字断言式文言）；简单逻辑直说；标题少用括号；**章节标题不得残留模板提示语（"≤N条/≤N个/（必要技术特征）"等上限或说明语只出现在模板与本节注记，不进成文标题）**；"公知"→"通用手段/常用手段"；特征编号用纯数字1、2、3（不用字母+数字组合）；删"（全文已通读）"式自证表述；不过度设防（D1–D10）。

## 文档头部

元信息做**表格**，字段集固定为：**案号、交底书名称、申请人/发明人、撰写人、撰写人电话、E-mail**（真实代理交底模板字段；未知项写`【待确认】`，docx 中自动红字）；其后"注意事项"三条（给代理人的阅读说明，过程稿整节红字、定稿按 docx-format §4 处置）。

## 缩略语和关键术语定义

文首集中定义后文高频术语与缩略语（每条：术语｜一句人话定义）。与 3.1 场景铺垫互补：此处定义"词"，3.1 铺垫"场景"。全文用词与本章逐字一致；改名后本章同步更新（零残留断言）。

## 一、技术背景与现有技术

**1.1 现有技术**——**先写一段总起引言**：用几句话把本交底的技术话题引进来，再点出现有技术集中在哪些方向；随后各段逐方向展开（每段：方向→代表做法→局限一句）。

- 有 D1（门禁"过/带疑点过"）：**D1 只用一段话介绍**（公开号＋名称＋一句它怎么做），不展开细节、不逐特征比对、不列特征一览；**随后另起一段写本发明与 D1 的区别**（"本发明与该方案的区别在于…"式，可按特征分组但不展开成表），D1 段与区别段**篇幅约 1:1**，区别段至多约为 D1 段的 2/3，不超长。
- 无 D1（门禁"不过"）：不点名、不编造；现有技术写材料所述做法与本领域常规；写明"本次未钉住可作最接近现有技术的对比文件"。
- **引用专利只列公开号与名称**（不写申请人单位、申请日、同族等——代理人按号自查）。

**1.2 现有技术存在的缺点**——≤6 条；每条完整中文句，落到 D1 或现有做法的**具体**不足；F 号禁用，编号纯数字；禁止"现有技术普遍存在不足"式套话；客观陈述不贬低。

## 二、本发明所要解决的技术问题

- 只写**效果导向的问题句**（要达到什么，不是怎么做）；问题句中**不得出现本发明手段词**。
- 多个特征功能上相互支持时**按整体写一条**问题，不拆条。

## 三、技术方案详细阐述

**3.1 应用场景与总体思路**（三小段铺垫）：①场景与参与者（用案件名称里的领域对象称呼执行主体）；②标题对象如何进入系统（从案件材料归纳）；③高频过程一句话引导（术语定义已在文首缩略语节，此处不重复定义）。

**3.2 系统框图**：fenced mermaid（`flowchart`＋`subgraph`）；节点标签用场景短词与标题领域对象；**图内不出现图名**（图名只在图题）。

**3.3 模块功能说明**：按 3.2 框图节点一项一模块，写作用与关联关系。

**3.4 方法流程**：fenced mermaid 流程图＋按 S1–Sn 步骤号逐项文字说明，图文一一对应。**步骤号写进节点可见标签**（`S1["S1 …"]`）。**若流程含前置输入准备步骤（步骤A、B等），在准备步骤结束与主链 S1 开始之间加一句过渡标识**（如"正式方法流程如下。"），使前置与主链分界可读。mermaid 围栏后紧跟图片行 `![图N　图题](图N_xxx.png|宽=…)`,宽度以单图不占整页为准（横幅≈560、纵向≈430 磅）。

**3.4.1 公式**（有公式时设）：
- **不用集中符号表**；改为**每条公式下方逐符号说明**（毕业论文式）："式中：x 为…；y 为…；下标 c 表示…"。
- 公式居中、编号（N）右对齐——md 写 `$$…$$`，docx 由 generate.js 自动排版；**禁止公式截图/图片**（含符号说明在内）。
- 公式与流程互推：每条主式能对上 3.4 某步或 3.3 某模块职责；材料已有式转录不改写；补写式在问题清单注明；边界情形（空输入/分母为零/达上下界）正文交代。

**3.5 关键技术参数**：参数表（参数｜符号/取值｜来源）；每个阈值/权重交代来源三选一（经验值/实验统计得到/可调范围），禁无出处魔法数；说明单调性更好。

## 四、替代方案与可选实施路径

前移独立成章（不再在 3.x 设"可选实施方式"，避免重复）。3–4 点，每点：某关键步骤/判据的等价替换＋指回 3.x 某步＋代价或适用场景。作用：给代理留权要收缩退路。材料或本领域公知能支撑的才写；推断性替代标"待确认"。

## 五、与现有技术相比的有益效果

≤6 条；每条**完整效果句**（构造写进句子，可句末括注编号）；无主优点禁写（"提升效率"不写清哪段构造带来的）；协同特征整体论述；数字效果溯源案件材料，不夸大。

## 六、技术关键点和欲保护点

先做**删除测试**：删掉某特征仍能解决第二章问题→归 6.2；否则归 6.1。

- **6.1 技术特征关键点**（必要技术特征，≤6 条）：每条＝`N．简称：特征全文复述（对应 3.4）`——**尾注只到章/步骤号一级**（"对应 3.4"或"对应 S1"二选一），不堆叠"式(n)"级引用、正文已注明对应关系的不再重复标注；**纯数字编号**（1、2、3…）；离开编号仍可读；**不写**"根据权利要求…"权项句式。
- **6.2 优选特征**：阈值取值、档位、可选分支、独立子主题；只剩参数差异的点归此，不硬写成独立创新点。
- ≥2 组无共同必要特征时：写明总发明构思或建议拆案。

## 七、实施例及其它

≤2 个实施例（主路径＋一条第三章已有分支）；**小节标题带 7.x 节号与实施例名**（"7.1 实施例一：〔主路径实施例名〕"、"7.2 实施例二：〔分支实施例名〕"）；实例有名字、带输入输出与交付物，名称与 3.1/3.2 同词；数字全部溯源案件材料，未实跑口径写"结构验证/试算"。

## 附图说明 / 参考文献（末尾两节，### 三级标题）

- 两节均为**三级标题（###）**，挂靠在第七章之后的小节级（不用二级章级）。
- 附图说明：逐图一行"图N　图题"（与正文图题逐字一致）。
- 参考文献：引用的对比专利**只列公开号与名称**；**不引用本地内部文件名**（本地资料仅作背景素材，不写入交底书引用）；条目尾部说明性括号过程稿红字。

## 脱敏与术语贯穿（成文后过一遍）

- 脱敏表：业务/行业→通用描述；具体分类→ABC；涉密数值→范围；公司/产品/内部代号→"某系统"。**勿把标题领域对象脱成空上位词**。
- 标题领域实词贯穿 3.2 框图、3.4 流程、第七章实施例（同一执行主体）；话题错位词整篇换领域表述；改术语＝整族替换（含缩略语节、mermaid 标签、图题）。
