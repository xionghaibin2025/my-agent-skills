# 权利要求草稿撰写规则（Step 7 必读）

先写一句话：`问题 → 手段 → 效果`（来自交底第二章与第六章）。材料只来自交底书——交底没写的**不补进**权利要求。**编号纪律**：交底与权利要求全程用纯数字编号（1、2、3…），不用"F1/Fk"这类字母+数字组合。

## 1. 独立权利要求（第 1 项）

- **取材**：只用交底 **6.1 技术特征关键点**（已按删除测试分好），不重新自行判断必要性；不把优选参数、数值、分支塞进独权。
- **方法独权句式**（方法类默认）：

  ```
  1. 一种[主题名称]方法，其特征在于，包括以下步骤：
     步骤一，[做A，得到/判定…]；
     步骤二，[基于步骤一的结果做B…]；
     …
     步骤N，[输出…]。
  ```

- **步骤名与交底流程图逐字同义**：每个"步骤N"必须能在交底 3.4 的 S1–Sn 与流程图节点 label 上对上（同义即可，不必逐字相同，但**不得**出现流程图里没有的步骤、不得漏掉必要步骤）。匹配细节（构成、双阈值含义、窗口长度等）只进从权。
- **不另编编号体系**：交底用 S1–Sn，权利要求用"步骤一/步骤二"；不要在权利要求里新造 S1、201 这类编号。
- **同时要求系统/装置时**：第二条独立权利要求只写模块名称及连接/功能关系，不写附图标记；写成独立权项，不写成从属。默认（用户未要求）只写方法独权，介质/设备权要在问题清单提示"可按需追加"。

## 2. 从属权利要求（第 2–N 项）

取交底 **6.2 优选特征**，按四层组织后再编号（层次记录在草稿附注，不进正式文本）：

| 层 | 写什么 | 支撑 |
|---|---|---|
| 优选参数 | 阈值、权重、窗口、间隔等交底已有取值 | 交底 3.5 参数表 |
| 分支 | 交底已写的例外、回环、不可行处理 | 交底 3.4 分支 |
| 系统对应 | 方法步骤对应的模块（仅当有系统独权） | 交底 3.3 |
| 实施例展开 | 仅实施细节，不升高独权 | 交底第七章 |

- 句式：`根据权利要求X所述的[主题]，其特征在于，[限定]。`——只引用在先权项；不引用在后的。
- 展开某步时用嵌套：`…其特征在于，所述步骤二中[限定]的方法如下：…`（仍用"步骤二"，不改 S2）。
- 同层不把互斥分支写成可同时成立的并列，除非交底明确是可选项。

## 3. 体例硬规则（逐条对照）

1. **"所述"须有前置**：该词在本项更早位置或在先引用权项中已出现；不写"一上来就所述匹配分"。
2. **公式入正文不入权要**：计算关系用文字限定（"按…加权并扣除…得到…"）；整段公式、LaTeX 不进权利要求。权要用语须与交底 3.4.1 符号含义同义。
3. **禁宣传语**："显著""极大提升""行业领先""最优方案"等一律删；效果表述放交底第四章。
4. **参数表/对照表不入权要**：数值例、表格只出现在交底/说明书位。
5. **无待确认标记**：正式草稿文本中不留"[待确认]""质量分"等过程标记；备选写法记入问题清单。
6. **引用基础完整**：每项的限定对象在引用链上有定义；权项之间不自相矛盾。
7. **主题名称一致**：各项"所述[主题]"与第 1 项主题名称逐字一致。
8. **歧义处置**：同一限定有多种可写法时，选交底能支撑的一种写入，其余记问题清单（备选权要），不阻塞。

## 4. 数量与结构基线

- 独权 1 条＋从权 6–10 条为常见区间（对应 6.2 的优选参数/分支/实施例三层）；交底 6.2 内容多时从权可到 12 条，不硬凑。
- 从权顺序：优选参数层→分支层→实施例展开层（由近及远）。
- 草稿末尾附**权项↔交底对照表**（权项号｜对应交底章节/步骤号｜对应特征编号）——供代理核对支持性，标注这是给代理的工作表，不是正式文件一部分。

## 5. 自检钩子（交付前跑一遍）

- [ ] 独权只含 6.1 特征？每个"步骤N"能在交底流程图上找到同义节点？
- [ ] 每条从权引用的权项号 < 本项号？互斥分支没写成并列？
- [ ] 每个"所述"有前置？全文无公式、无宣传语、无待确认标记？
- [ ] 主题名称逐字一致？编号纯数字（无 F1/Fk 字母组合）？权项↔交底对照表已附？
