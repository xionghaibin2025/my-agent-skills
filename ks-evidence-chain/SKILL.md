# 证据链：从代码到投稿包

## 用途

适用于脚本多轮迭代、结果目录和稿件版本较多的长周期项目，管四件事：新项目目录骨架、迭代期的产物纪律、定稿前的普查、投稿包整理与能否投稿的裁决。新建论文项目时按 `references/project-skeleton.md` 建目录（单论文与多论文两个变体）。

不用于单次数据分析出报告和逐句润色（`ks-paper-polish`）。

## 一、三类错误，只有一类能被字符串核对查出

常见的数字核对是把手稿里的数当字符串，去结果表里搜是否存在，只能查出 A 类。

**A 类｜值错**：数字对不上任何一次真实计算。字符串核对能查出。

**B 类｜话错**：数字算得没错，但**那句话把它说成了别的量**。数字确实在表里，字符串核对查不出。
- 正文写"合并所有留出预测后计算"，代码是逐折算再平均。两者在空间块设计下能差 0.07。
- 正文写"高程与模型输出的相关 ρ = −0.97"，代码算的是高程与它自身那一列 SHAP 贡献的相关；与模型输出是 −0.70。
- 正文写"至多 0.991""从未超过"，代码给的是若干个极值的平均，真实上界是 1.000。

**C 类｜链断**：数字对、话也对，但它背后的归档件已经过期、已被覆盖、或根本没有脚本产出它。
- 论文改了口径，公开数据包的导出脚本没跟着改，复现者算出的数和正文对不上。
- 手工改了某个文件，而该文件由生成脚本整体重写，下次重建就被抹掉。
- 某个结果目录没有任何脚本会写入它，也没有任何表会读取它，来源不明。

B 类和 C 类是定稿阶段的主要风险。盲审是抽样，查不全，需要按第三节普查。

## 二、迭代期的八条约束

**1. 结果脚本必须能改输出目录，且默认不写归档目录。**
用环境变量或命令行参数覆盖输出路径。归档目录只读。曾发生：重跑一个换了参数的实验，直接覆盖了上一组参数的归档结果，因为输出路径写死在脚本里。

**2. 每个结果目录里放一份运行元数据。**至少包含：产出它的脚本名、脚本的 git 版本或修改时间、关键参数（种子、情景、阈值）、运行时间、依赖的上游结果目录（若有）、`pip freeze` 摘要一行、结果主文件的 md5。元数据用于判断目录是否仍在使用，哈希用于发现结果被改动。不在 git 下的项目，在归档目录保留旧版本并在过程文档中记录，元数据记录脚本 md5。

**3. 不要从旧版结果里回填新版指标。**若必须回填，加一个显式开关，并把两边的参数一起写进元数据。曾发生：v2 脚本从 v1 的 CSV 回填了八列旧指标，把两组不同参数的结果混在一张表里，靠某个均值精确到小数点后六位相同才被发现。

**4. 生成物不要手工改。**凡是由脚本整体重写的文件（结果表、补充材料），要改就改生成脚本。手工加的内容下次重建即消失。

**5. 报告值的定义写进脚本注释，不只写进论文。**特别是聚合口径（合并池 / 分组平均）、极值还是均值、相关的是哪两个数组、计数的分母是什么集合。B 类错误多源于这四件事在代码和论文里说法不一。投稿包里只保留这类注释，其余按 `references/code-release.md` 清掉。

**6. 派发给其他模型跑长清单时，要求它自己逐条做、逐条落盘。**任务书写死三条：不再向下转派子代理；"每完成一项立刻追加写入输出文件，不要攒到最后"；完成与否看产物，不凭退出码。曾发生：模型计划把 22 个条目分给子代理，最终没有写出任何内容，退出码仍为 0。大文件要求用 `sed -n 'a,bp'` 分段读，不反复用整文件读取工具尝试。

**7. 脚本被取代时，旧版立刻标记归档，同一时刻只留一个现役版本。**AI 迭代脚本时常另起 `xxx_v2.py` 而保留旧版，几个月后十几个版本并存，分不清哪个是现役版本。做法：
- 旧版改名加前缀（如 `deprecated_v1_原脚本名.py`）或移入 `attic/` 子目录。用前缀不用后缀，`ls` 时废弃脚本排在一起。
- 新脚本头部注释写明"取代了谁、口径改了什么"，据此判断新旧结果是否可比。
- 旧脚本产出的结果目录同步标记废弃（加 `superseded_` 前缀保留，不删除，失败和被取代的运行也是证据），否则会出现脚本已废弃、结果目录仍被引用的断链。
- 版本管理二选一：在原文件上改，靠 git 记录演进；或出新文件，靠改名归档旧文件。不允许改了旧文件不提交、同时又留一个同名新文件。

**8. 代码和题注在写出来时就按投稿标准写。**脚本按 `references/code-release.md` 的"代码风格"写，第 7 条的取代说明照留；绘图、出表脚本生成的图名、图注、表名、表注按 `ks-paper-polish` 的 `references/captions.md` 写，解释、辩护、制图记录不进题注。这两类文字大多在写代码时产生，打包时再删，要连同引用它们的正文和补充材料一起返工。

## 三、定稿前：溯源账本与论断核对

核对前先确认现役稿件与配套文件：正文、cover letter、审稿答复、图表、补充材料、来源数据与分析输出，以项目文件里明确指定的版本为准，不用桌面或临时副本；过期版本标出来，不参与核对。缺的东西记为缺失，不推断。

### 数字层：溯源账本

对**摘要、结果、讨论三节的每一个数值**建账，一行一个数：

| 手稿位置 | 原句 | 这句声称它是什么量 | 计算它的脚本与函数 | 归档文件与列名 | 重算值 | 判定 |

判定四档：**一致 / 值不符 / 描述不符 / 无法追溯**。

- "描述不符"是重点，指数值对得上但那句话把它说成了别的东西。
- 判为"一致"的关键值，**至少从归档原始文件重算一次**，不能只比对结果表里的字符串。
- 追溯不到的写"无法追溯"并说明找过哪里，**不要按手稿的值填**。

方法节里的参数设置另列一节，从简。

尽量写脚本批量做。可参考 `references/ledger_template.md` 的表头与判定口径。

### 六类口径专项检查

逐数字核对之外，另查以下六类容易"值对而话错"的地方：

1. **聚合口径**：报告交叉验证指标处，正文说的是合并所有留出预测后计算，还是各折分别计算再平均？代码是哪种？两者在此处会不会给出不同的数？
2. **均值还是极值**：正文用"最大""至多""从未超过"处，代码算的是真极值，还是若干极值的平均？
3. **相关的两个变量**：每处相关系数，正文说的两个变量与代码里实际相关的两个数组是不是同一对？
4. **计数的分母**：所有 `x/y`，分母是哪个集合？正文说的分母与代码里的一致吗？
5. **单位与变换**：原值与对数值混用处；反变换有没有加 smearing；长度单位。
6. **样本量**：每个样本量数字出现的各处，指的是不是同一个集合。

### 论断层：主张对证据

摘要、结论、highlights、cover letter 和审稿答复里每一条决定性论断，逐条核对：

- 分析单位是什么：记录、样点、剖面、井、事件。样本数、排除、分母、阈值、置信区间、单位与正文一致。
- 方法能支撑到哪一层：检测、关联、预测、解释、因果或来源归因。论断不得越过方法所在的层。
- 新颖性、普适性、验证、影响的说法有没有超出包内的证据。
- 正文、摘要、highlights、cover letter、审稿答复、图表、补充材料之间互相一致。

判定四档：**成立 / 收窄措辞后成立 / 未核验 / 矛盾**。收窄措辞的改法交 `ks-paper-polish`。

### 引文层：主张对被引文献

引言、讨论和方法中依赖文献的事实性主张，逐条核对被引来源是否支持这句话。文献存在、引用格式正确、来源支持主张是三件事，前两件不能代替第三件。

- 一条记录只核一个可判断的主张；一句含多个主张时拆开，各自对应引文。
- 记录来源定位：页码、表号、图号或段落。判"支持"必须有定位；只确认 DOI 或题名存在，不算核过。
- 写明读到哪一层：全文、仅摘要、转引。摘要不支持摘要未报告的细节；转引要回到原始来源，取不到原始来源的判为无法取得全文。
- 比对项：研究对象与区域、时间、变量与量的定义、方向、数值与分母、不确定性，以及来源的设计能否支撑当前措辞。常见错位：单一区域的结果被写成普遍规律，综述里的"有潜力"被写成"已证实"，来源讨论的是相近而不同的量。

判定五档：**支持 / 收窄措辞后支持 / 不支持 / 曲解 / 无法取得全文**。曲解指来源被夸大、方向反了或丢了限定条件。"无法取得全文"不算支持，写明试过哪些入口。不支持与曲解列为阻塞项，处理方式是收窄措辞、换来源或删句，改完重核。记录表见 `references/ledger_template.md`。

### 投稿前审稿式自查与真实意见回复

需要以审稿视角定位薄弱点，或把真实审稿意见变成工作项时，每项写清位置、影响、所需动作和状态。问题必须回到稿件、代码、归档或明确缺失的材料；不模拟多位独立审稿人。未完成的实验、分析或修改如实标为待办，不写成已解决。

以外部打假者视角筛查数值规律、图像复用、与本组已发表论文的重复、引用中的撤稿文献，按 `ks-integrity-audit` 的自查模式执行，其发现清单并入本节裁决。

### 图件红线

- 图注承诺的内容必须画出来；正文引用的统计量必须能从归档数据复算，复算不出的要么补数据要么删除。
- 图上任何非本研究数据的线（判别域、端元场、边界曲线）要能溯源并验证；定稿前验证不了的删除或换成可溯源的来源，不用图注说明代替。
- 引用数据须与来源（原始表、归档表、运行记录）一致。

### 独立性

账本与论断核对由**未参与写作的执行者在隔离上下文中**做，只给它手稿、代码与归档，不告诉它作者认为哪里没问题。独立性按风险配，跨厂商模型只是补充证据，关键值由编排者独立重跑确认；约束见全局文件的学术节。

## 四、投稿包与裁决

投稿包的读者是编辑与审稿人。目录名要能直接看出哪些随投稿提交、哪些不提交。

一份可用的结构：

```
01_主文稿/        正文（与源文件逐字节相同）
02_主文图件/      Figure_1..N，投稿格式与矢量各一份
03_补充材料/      补充材料正文 + 补充图 + 大表
04_投稿信与声明/  cover letter、声明汇总、关联稿件副本
05_代码与数据/    全部代码 + 去标识数据包 + 结果表（归档拿 DOI 后以链接提交）
06_内部材料_不随投稿提交/   审查裁定、审计原始材料、变更清单
```

审查底稿、模型判定、内部裁决只放最后一个目录，不上传投稿系统。

`05_代码与数据/` 的披露范围、README、路径与隐私卫生、注释规范按 `references/code-release.md`。必备件与声明是否齐全、残留标记扫描、期刊硬性项按 `references/submission-completeness.md`。

包内自查（可脚本化）：

- 包内主文稿与源文件逐字节相同
- 正文引用的每个图号表号都有对应文件，反向也没有"有文件但正文没引"
- 图件无异常小文件（生成失败会留下几 KB 的空图）
- 图名、表名不超过 15 个词；多面板图注超过 60 个词或单句超过 25 个词的逐条按 `captions.md` 删改，期刊另有规定的按期刊
- `05_代码与数据/` 只含关键数字的依赖闭包，脚本无 AI 式冗余，按 `references/code-release.md`
- 除已知占位符外无遗留标记（TODO、待补、XXX）、编者注与内部批注、修订痕迹、批注、断裂公式
- 无未定义缩写与前后不一的术语
- 无本机绝对路径、内部文件名、保密坐标、个人数据、非目标语言残留
- 期刊要求的声明齐全，含利益冲突、资助、作者贡献、数据与代码可用性、生成式 AI 使用声明
- 审稿答复里的页码行号指向当前版本
- 期刊要求的结构、文件命名、表格样式、模板约束已核对
- DOCX、PDF、表格的版式用渲染后的成品目视检查；不能渲染时说明这一限制，继续做源码层面的检查
- 防御性写作审计跑过一遍，按 `ks-paper-polish` 的 `defensive-writing.md` 审计模式
- AI 痕迹审计跑过一遍，按 `ks-paper-polish` 的 `ai-trace-audit.md`；未跑过不视为完成语言检查
- 公开数据包只用包里的文件、不依赖仓库其余部分，能复算出正文的关键数字。这一条最容易漏；审稿人用数据包算出与正文不同的数，会质疑结果本身。

裁决只有三档：

- **可投**：没有决定性阻塞项。
- **有条件可投**：只剩有边界的修改，不需要新分析。
- **不可投**：论断、证据、溯源、隐私或必备材料仍有阻塞项。

发现分四组报告：阻塞项；投稿前必改；可选改进；过期或纯风格、不该引起返工的意见。裁决从列出的证据推出，未解决的限制明确写出。缺失的模型输出或溯源按缺失证据处理，不用文字说明代替。

## 五、常见坑

`references/incidents.md` 按类别记录真实发生过的错误、发现方式与修法。多数问题会重复出现，定稿核对前先读一遍。

## 输出

核对任务只新建报告文件，不改手稿、代码与归档；需要改稿件时按裁决交 `ks-paper-polish` 或经用户授权后再改。

- 溯源账本：`溯源/ledger.md`（目录骨架见 `references/project-skeleton.md`）
- 论断核对与口径专项结论：并入账本
- 投稿包自查结果与裁决：随包放 `00_README.md`
