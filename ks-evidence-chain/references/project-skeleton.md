# 论文项目目录骨架正本

原则：根目录只放规则与过程（AGENTS.md、CLAUDE.md、PROCESS.md、MEMORY.md、DECISIONS.md），一切产物进目录；两篇以上论文共用的进共享层，专属的进论文目录；大型临时文件放本地临时目录，不进 OneDrive。本文件是目录设计正本；项目 AGENTS.md 只写一行指向本文件，并列出本项目的偏离。

## 单论文项目

```text
AGENTS.md  CLAUDE.md
PROCESS.md              当前进度、待办、下一步，唯一入口
MEMORY.md               跨任务稳定事实
DECISIONS.md            方法决定与变更原因，追加式
文献/                   参考文献，只读
数据/                   raw/（原始，只读） + processed/
代码/                   脚本 + 配置 + tests/
结果/                   脚本产物，每个目录自带运行元数据
溯源/                   定稿前逐数字溯源账本（ledger.md）
稿件/                   正文各版本 + 补充材料
投稿包/                 定稿打包出口（见 SKILL.md 第四节）
归档/                   deprecated_/superseded_，只进不出
```

## 多论文项目

共享层 + 每篇论文一个目录，论文目录内部是单论文模板的产物层：

```text
AGENTS.md  CLAUDE.md
PROCESS.md              总索引：一行一论文 + 当前优先级
MEMORY.md  DECISIONS.md
文献/  数据/            共享层：≥2 篇论文用到的才放这里
论文-<主题>/
  …                     每篇一个目录，内含与单论文相同的产物层
                        （数据/ 代码/ 结果/ 稿件/ 投稿包/）+ 进度.md；
                        仅一篇专用的数据与文献留在该论文目录内
归档/
```

目录命名用主题短词（如 `论文-盐分机制/`、`论文-TFS方法/`），不用序号做主名。论文的优先级和拆分会变（曾有项目改方案后三篇论文顺序对调），序号会与实际地位脱节；PROCESS.md 里按主题名指代。序号只允许出现在排序需求明确的地方（如投稿包内文件编号）。

## 相对早期项目结构的合并关系

- `日志/`、`计算过程/` → 取消，运行记录随各结果目录的运行元数据走
- `草稿箱/` → 取消，大型临时文件放本地临时目录
- `测试/` → 并入 `代码/tests/`
- `待办包/` → 并入 PROCESS.md
- 早期 `文档/` → 拆为根目录三个 md

## 落地方式

- 新项目：按源仓 `my-skills` 的 `global/project-agents-template.md` 骨架填写项目 AGENTS.md，按本文件建目录。
- 已有项目：不动现役路径（改路径本身破坏可追溯性），收敛推迟到里程碑（如投稿包定稿）之后，届时更新目录映射文档。
