# 任务预设与落盘矩阵

先按 [workflow.md](workflow.md) 完成身份核验，再选定预设。预设只补全用户未指定项；用户明确的路径、格式、命名直接沿用。

## 四个预设

### 1. 单篇翻译归档（默认）

适用：一篇论文 → 双语对照 MD + 截图 + 补充材料。完整走 workflow 阶段 1–10。

两个入口变体（阶段 2 判定，产物结构相同）：

- **入口 A（paper-fetch 先行）**：`补充材料/` 复制自 paper-fetch 归档（或按用户要求原位引用）；文本底本优先用归档的 provider markdown。
- **入口 B（自备 PDF）**：补充材料由本技能委托 paper-fetch（`asset_profile=all`）获取；PDF 直提文本为底本，委托返回的 markdown 可替换为首选底本。

产物目录（默认 `<输出根>/<论文名>/`，用户指定时沿用）：

```
<论文名>/
├── <论文名>_双语对照.md          # 主交付
├── <论文名>_双语对照.说明.md      # 主交付说明
├── 图片/
│   ├── Fig01_描述.png …          # 300 DPI 渲染截图（图号即文件序）
│   ├── 整页/pageNN.png           # 对照验收证据（150 DPI 整页渲染）
│   └── 渲染报告.json
├── 补充材料/                      # paper-fetch asset_profile=all 归档（可能为空）
└── 工作区/                       # 中间产物（结构、分块、验收 JSON）
```

### 2. 批量翻译归档

适用：多篇论文。每篇沿用预设 1，另在输出根目录维护 `进度.json`（原始 index 映射）与 `结果说明.md`。各论文独立推进；同 DOI 去重后只处理一次。

### 3. 仅提取不翻译

适用：用户只要截图和/或结构化文本，不要译文。走阶段 1–5 后止；产物只有 `图片/` 与 `工作区/结构/`，不建双语 MD，也不触发翻译相关验收分面。

### 4. 修复续跑

适用：已有交付物局部修复——重截某几张图、重译某几块、补下补充材料。先读 `进度.json` 与 `验收.json` 定位缺陷，只重做受影响阶段，然后重跑 merge_verify 全量校验。覆盖已有交付按 `overwrite_existing` 处理（修复类覆盖若用户已在指令中点名目标文件，视为已授权）。

## 落盘矩阵

| 预设 | 双语 MD | 截图 PNG | 整页对照图 | 结构/分块/验收 | 补充材料 | 说明文件 |
|---|---|---|---|---|---|---|
| 1 单篇 | 写 | 写 | 写（`图片/整页/`） | 写（`工作区/`） | paper-fetch 可用时写 | 主交付 + 图片集合 |
| 2 批量 | 每篇写 | 每篇写 | 每篇写 | 每篇写 + `进度.json` | 同上 | 每篇 + 总 `结果说明.md` |
| 3 仅提取 | 不写 | 写 | 写 | 写 | 按用户要求 | 图片集合 |
| 4 修复 | 重写受影响 | 重写受影响 | 重写受影响 | 重写 | 补齐缺失 | 同步更新 |

硬性规则：

- 中间产物只进 `工作区/`，不与交付件混放；交付后 `工作区/` 可归档保留（复算依据）。
- 任何交付件覆盖前，旧文件移入 `工作区/旧版/` 而非直接删除。
- 翻译由宿主完成，不存在"译文脚本输出"；`块*_译文.md` 属中间产物。

## 产物命名

- 双语 MD：`<论文名>_双语对照.md`；论文名 = `<一作姓><年份>_<中文简称>`（如 `Smith2022_植被韧性全球转变`），用户另有命名直接沿用。
- 截图：`Fig<两位序号>_<中文短描述>.png`；Extended Data 图用 `EDFig<序号>_`。中文短描述来自图注首句的宿主概括，不逐字翻译。
- 纯中文模式（用户明确要求时）：译文块去掉英文引用块，验收分面 `coverage` 改查段落覆盖率（无配对率），其余不变。

## 说明文件纪律

每个非说明类交付物配同主文件名 `.说明.md`（图片可合并为一份 `图片.说明.md` 集合说明 + 清单）。双语 MD 的说明至少写：底本 PDF 来源与 DOI、生成日期、翻译范围（摘要→结论）、截图方法（渲染法/坐标覆盖）、公式重建与待确认数、参考文献处理、已知限制。该规则使产物在带归档纪律的工作区自动合规，在普通环境也是可追溯实践。
