# 工作流：状态机与推进规则

每篇论文是一个独立状态项，整批任务共享意图、输出与并发策略。阶段顺序固定：

> 身份核验 → 资产准备 → 结构提取 → 图渲染 → 截图对照验收 → 分块 → 翻译 → 合并校验 → 验收 → 报告

阶段必须有序；批量任务中身份明确的论文独立推进，一篇暂停不阻塞其余（用户要求整批原子完成时除外）。

## BLOCKING 白名单

仅以下五类情况可以暂停并请求用户决定：

- `identity_mismatch`：本地 PDF 的 DOI/标题与用户声称的论文对不上。
- `source_unusable`：PDF 损坏或不可解析，且自动重新获取失败（含 paper-fetch 不可用）。
- `figure_layout_unresolved`：图注自动定位失败或明显漏检（如正文引用了 Fig.7 但只定位到 6 个图注），且 `--coords` 手工覆盖无法确定。
- `overwrite_existing`：继续会覆盖已有且可用的双语 MD，用户尚未授权。
- `material_output_choice`：输出目录、对照格式（双语/纯中文）、图片命名等多个无法自动推断的选择会实质改变产物。

不得因以下原因暂停：没讨论保存细节、图片较多、某张图渲染降级、公式需重建、补充材料缺失（记 degraded 继续）、paper-fetch 不可用（走本地降级）。沿用用户本次任务中已做的明确选择，不因进入新阶段重复询问。

## 阶段细则

### 1. 身份核验

- 输入：本地 PDF 路径、DOI、或 paper-fetch 已归档的目录。
- 本地 PDF：运行 `pdf_structure.py` 生成元数据（含从首页文本探测的 DOI）；DOI 或标题与用户描述核对。对不上 → `identity_mismatch`。
- 只有 DOI/标题没有 PDF：直接进入资产准备，由 paper-fetch 解析身份。

### 2. 资产准备（先判定入口，再按决策树执行）

任务开始先判定入口属于哪一种，两种入口的补充材料分工不同：

**入口 A：paper-fetch-skill 先行获取**（用户已自己让 paper-fetch 下载，或给出 paper-fetch 归档目录/其 DOI 证明的 markdown）。补充材料的下载在获取步骤已由 paper-fetch-skill 完成，本技能**只定位与复用其归档产物，不再触发任何下载**：

1. 定位归档：用户给的目录、或归档索引中该 DOI 的条目；核对 PDF、provider markdown、资产清单三者的存在性。
2. 文本底本：优先用归档中的 provider markdown（公式损失最小）；PDF 仅用于截图渲染。
3. 补充材料：直接复用归档；默认复制进 `<论文产物目录>/补充材料/` 保证交付自包含（说明文件记录来源路径），用户明确"不复制只引用"时沿用原位。归档缺补充材料时如实报告（asset 分面记"归档未含"），**只有用户在本次翻译请求中明确要求补充材料时**才补一次委托下载，并在报告注明是补齐动作。

**入口 B：用户自备本地 PDF**。全文底本与截图用本地 PDF；补充材料由本技能负责，委托 paper-fetch-skill 补齐：

1. 本地 PDF 可打开、页数合理、文本层非空 → 直接用作底本与渲染源；损坏则转委托重获（DOI 已知时成功率最高），重获失败走 `source_unusable`。
2. 补充材料：委托 paper-fetch-skill"单篇本地归档"预设并显式 `asset_profile=all`，取归档中的补充材料部分（主文 markdown 会一并返回，属正常现象，可顺带作为文本底本首选，见 extraction.md）。paper-fetch 不可用或获取失败：asset 分面记未获取（degraded），不阻塞翻译交付。
3. 用户明确说"不要补充材料"时跳过委托，asset 分面记"用户未要求"。

两入口共用规则：同一 DOI 已有合格双语 MD 直接复用不重翻译；身份核验在阶段 1 已完成；paper-fetch 的 acceptance 结论原样沿用，不重复验收其已核验的资产。

### 3. 结构提取

运行 `pdf_structure.py <pdf> --out <工作目录>/结构/`，产出逐页文本、`结构.json`（图注定位）、图片盘点、元数据。文本底本选择（PDF 提取 vs paper-fetch 的 provider markdown）见 [extraction.md](extraction.md)。

### 4. 图渲染

运行 `render_figures.py`（参数见 figures.md），产出 `图片/FigNN_*.png` + `图片/整页/pageNN.png` + `渲染报告.json`。图注定位数与 `结构.json` 一致性核对，异常走 failure-handling。

### 5. 截图对照验收

宿主逐图核对：截图内容与整页参考图中该图位置一致、面板完整、无题注/页眉混入。可疑图标记 `figure_suspect` 并按 failure-handling 重渲或手工坐标。**未完成本阶段的图不得进入译文链接。**

### 6. 分块

运行 `chunk_split.py`，把清理后的全文切成 ~6000 字符的段落边界块（`块01_原文.md`…）。块清单含字符数与覆盖范围。

### 7. 翻译（宿主）

逐块读取原文块，写同号译文块 `块01_译文.md`：英文原段为 `> ` 引用块，紧接中文译文；该块涉及的图片在此处以相对路径插入；公式以 LaTeX 重建，假设处标"待确认"；参考文献保留英文。翻译中途发现截图缺陷可回阶段 4-5 修复后继续。

### 8. 合并校验

运行 `merge_verify.py`，合并全部译文块为 `<论文名>_双语对照.md` 并输出 `验收.json`。断链≠0 或配对率低于预设阈值时按 failure-handling 修复后重跑。

### 9. 验收

按 [acceptance.md](acceptance.md) 的分面核对 `验收.json` 与实际文件；补充材料状态沿用 paper-fetch 的 acceptance。

### 10. 报告

单篇：产物路径、验收分面结论、降级项（待确认公式数、缺图、缺补充材料）。批量：附进度总表。

## 批量进度

批量任务在产物根目录维护 `进度.json`：

```json
{"papers": [{"index": 1, "id": "Smith2022", "doi": "10.1038/...", "stage": "翻译", "status": "进行中"}]}
```

- `index` 为用户原始输入的 1-based 序号，全程不变；同一 DOI 重复输入合并到规范目标并保留别名映射。
- 每完成一个阶段更新 `stage`；终态为 `完成 / 降级完成 / 失败 / 待用户`。
- 续跑任务先读 `进度.json`，从各论文当前阶段继续，不重做已完成阶段。
